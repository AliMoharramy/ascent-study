# 09 — برنامهٔ پیاده‌سازی (Implementation Plan)

> سازنده: AI (مرحله‌به‌مرحله، با دستور «برو مرحلهٔ بعد» از کاربر). سرور/استقرار را کاربر خودش انجام می‌دهد.
> قانون طلایی: **ساختن سایت نباید زمان درس را بگیرد** (ضد‌هدف A1). بنابراین: سهم زمان کاربر هر انتشار ≤ ۱۵ دقیقه، **Build Freeze از هفتهٔ ۱۶**.
> تاریخ‌ها «هدف» هستند و با سرعت واقعی ساخت تغییر می‌کنند.

## 1. اصول اجرا

1. **Spec‑driven:** هر کار به یک ID فیچر (سند 06) و معیار پذیرش لینک می‌شود.
2. **Vertical slice:** هر انتشار قابل‌استفاده در همان روز است (نه لایه‌به‌لایه).
3. **Engines اول، UI بعد:** موتورهای دامنه با TDD و جدول سناریوها (سند 04 §12) پیش از UI نوشته می‌شوند.
4. **بدون اضافه‌کاری:** هر چیزی خارج از Spec به «Backlog» می‌رود؛ فقط با تأیید کاربر وارد انتشار.
5. **تصمیم‌ها در Decision Log (ADR) ثبت شوند.**
6. **Build Freeze:** از شروع هفتهٔ ۱۶ (7 اسفند) فقط رفع باگ. (ترجیح کاربر: «درس اولویت اول و آخر»).
7. **هر انتشار = Demo ≤ ۵ دقیقه + چک‌لیست پذیرش** و بعد تأیید کاربر.

## 3. کیت روز صفر (قبل از آماده شدن سایت)

چون Ch.1 فردا (23 آبان) شروع می‌شود و R0 دیرتر می‌رسد:
1. **Baseline Template** (یادداشت/کاغذ) برای ۲–۳ روز: ساعت بیدار/خواب، بلوک‌های مطالعه (شروع/پایان)، تعداد تست (درست/غلط/نزده)، انرژی ۱–۵ (۳ بار)، مانع و فرار، حضور کلاس.
2. بعد از R0 همه به‌صورت یک‌جا Import می‌شوند (F-LOG-06 manual).
3. هیچ XP/جریمه‌ای در این مدت وجود ندارد.

## 6. پروتکل کار AI (چگونه «مرحله به مرحله» پیش برویم)

1. کاربر می‌گوید: «برو R0».
2. AI قبل از شروع: لیست کارهای انتشار + معیارهای پذیرش + «چه چیزی از شما می‌خواهم» (≤ ۱۵ دقیقه).
3. AI موتورها را با TDD می‌سازد؛ سپس UI؛ سپس Demo script.
4. در پایان: گزارش (انجام شد/نشد، تست‌ها، لینک Demo، تغییرات نسبت به Spec، تصمیم‌های ثبت‌شده).
5. کاربر Demo را تست و «تأیید» یا «اصلاحات» می‌دهد؛ فقط بعد از تأیید انتشار بعدی.
6. هر پیشنهاد جدید کاربر → Backlog با برچسب (Spec change) و تأثیر روی زمان/جدول.

### Definition of Done (هر کار)
- کد + تست‌ها سبز؛ AC برآورده؛ بدون TODO باز؛ لاگ/ADR در صورت تصمیم؛ مستند به‌روز؛ Demo.

## 7. استراتژی تست و پذیرش
- هر موتور دامنه: جدول سناریوها از سند 04 §12 + Property‑based.
- «شبیه‌ساز ۲۵ هفته»: اسکریپتی که داده‌ی مصنوعی تولید و Rollover را اجرا می‌کند؛ هدف: بدون خطا، XP/SS درون محدوده، Load Ratio منطقی.
- Replay Test برای رویدادها.
- E2E ۱۰ سناریو (سند 07 §9).
- آزمون پذیرش کاربر (UAT): کاربر با «لیست ۸ کار» (ثبت تست، Surge، Miss+Shield، Boss، Council…) بررسی می‌کند.

## 8. مهاجرت داده و Seed
- Seed اولیه از `docs/seed/subjects.yaml` و `mock-exams.yaml`.
- Import لیست جلسات (کاربر).
- Import تاریخچهٔ کیت روز صفر.
- نسخه‌های Config: `v1` (پیش‌فرض)، `v2` (پس از Baseline).

## 9. ریسک‌های اجرا

| ریسک | کاهش |

| ساخت سایت وقت درس را می‌گیرد | ≤ ۱۵ دقیقه/انتشار؛ Build Freeze 7 اسفند؛ گزارش ضد‌هدف |
